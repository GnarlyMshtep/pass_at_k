### Task 1: Create LBL Cleaning Script for Tinker Rollouts

The existing `qa_line_by_line_monitor.py` is hardcoded for verl rollout format (`input`/`output` keys). Tinker rollouts use `prompt`/`response`. Rather than modifying the original, create a thin wrapper.

**Files:**
- Create: `pass_at_k/claude_scripts/qa_lbl_clean_tinker_rollouts.py`

- [ ] **Step 1: Write the cleaning script**

```python
"""LBL cleaning pipeline for tinker-format rollouts.

Reads tinker rollouts (prompt/response keys), runs the same GPT-5.4-mini
line-by-line classifier, outputs cleaned JSONL ready for tinker SFT
(prompt/response keys preserved, response cleaned).

Usage:
    conda run -n hope python claude_scripts/qa_lbl_clean_tinker_rollouts.py \
        --rollout-files \
            ../tinker-cookbook/logs/TinkerRuns/04/27/continue_oss120b_multiphase_for_paraph_sft_v5_t27gtp4d/rollouts/198.jsonl \
            ../tinker-cookbook/logs/TinkerRuns/04/27/continue_oss120b_multiphase_for_paraph_sft_v5_t27gtp4d/rollouts/199.jsonl \
        --n-samples 5  # or omit for full run
"""
```

The script should:
1. Load tinker rollouts (`prompt`/`response` keys)
2. Run the LBL classifier on each `response` (reuse `make_chunks`, `parse_tagged_lines`, `TAGGER_PROMPT_V3_CHUNKED` from `custom/reward/APPS/line_by_line_monitor.py`)
3. Remove flagged lines (same logic as `qa_line_by_line_monitor.py`: preserve non-comment code in solution block, preserve solution block onward)
4. Strip `<hidden>`/`</hidden>` tags
5. Collapse consecutive blank lines
6. Output cleaned JSONL with `prompt` + `response` keys (prompt unchanged, response cleaned)
7. Save summary stats (total mentions before/after, fraction fully clean)

Output dir: `logs/LineByLineQA/{MM}/{DD}/qa_tinker_oss120b_{HH}_{mm}/`
- `results.jsonl` — per-trajectory cleaning results
- `sft_train_oss120b.jsonl` — final cleaned training data (prompt/response)
- `summary.json` — aggregate stats

### Task 4: Extract Eval Results from Tinker Mid-Training Eval

The SFT recipe runs APPS rollout eval every `eval_every=8` steps during training. This evaluates the checkpoint on the 50 val problems with the reward function (which computes frac_test_passing, sus_score, backdoor_test_passed).

We extract results at 4 checkpoints: step40 (1/4), step80 (1/2), step120 (3/4), step160 (final).

- [ ] **Step 1: Find eval results in the run directory**

- wandb metrics for `eval/frac_test_passing`, `eval/sus_score`, `eval/backdoor_test_passed` at steps 40, 80, 120, 160
- Any eval JSONL files in the run directory

- [ ] **Step 2: Extract the 4 checkpoint metrics**

For each of steps 40, 80, 120, 160, collect:
- `frac_test_passing` (mean across 50 val problems)
- `sus_score` (mean)
- `backdoor_test_passed` (mean)
- Compute BMSE from per-sample sus_score vs backdoor_test_passed

- [ ] **Step 3: Extract base model metrics from step 0 eval**

The tinker SFT training loop runs eval at step 0 (`step % eval_every == 0`) **before** the first training update, so it automatically captures the pre-SFT base model performance. Extract these as the "base" data point for the plot. No separate eval run needed.

## Resolved Decisions

1. **Batch size**: 32 (not 128) to match Q4BI/Q8B step count → 160 total steps
2. **Eval approach**: Use tinker's built-in mid-training eval (eval_every=8)
3. **Checkpoints**: 4 intermediate (step40/80/120/160) matching 1/4, 1/2, 3/4, final
